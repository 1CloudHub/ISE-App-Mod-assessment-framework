Sessions 3-5: Workflow Deep Dives¶

Overview¶

Sessions 3-5 focus on detailed analysis of key business workflows within the legacy application. These sessions map out how the system implements business processes, identify pain points, and document functional requirements for modernization.

Pre-Session Activities¶

Assessment Team Preparation¶

  • Analyze available business workflows and process documents
  • Review relevant code paths for each workflow
  • Prepare workflow mapping templates
  • Use Amazon Q Developer to analyze workflow implementations

Customer Team Preparation¶

  • Review and update internal workflow processes
  • Identify subject matter experts for each workflow
  • Document known issues or limitations in current workflows
  • Prepare examples of typical workflow execution

Session Activities¶

Workflow Mapping¶

  • Document end-to-end business processes
  • Identify actors and their interactions with the system
  • Map user journeys and experience flows
  • Document business rules and decision points

Sequence Diagram Creation¶

  • Create detailed sequence diagrams for each workflow
  • Document component interactions
  • Identify synchronous and asynchronous operations
  • Map error handling and exception flows

Functional Flow Documentation¶

  • Document functional requirements for each workflow
  • Identify business constraints and validation rules
  • Map data transformations and state changes
  • Document integration points with external systems

Deliverables¶

Functional Requirements Document (FRD)¶

The FRD includes: - Detailed functional requirements by workflow - Business rules and validation criteria - User interaction specifications - Data requirements and transformations - Integration requirements

Sequence Diagrams¶

The sequence diagrams visualize: - Step-by-step flow of operations - Component interactions - Data exchanges - Decision points and alternative flows - Error handling paths

Workflow Coverage¶

These sessions typically cover the following types of workflows:

Session 3: Core Business Workflows¶

  • Primary user journeys
  • Main business operations
  • Critical transaction flows

Session 4: Supporting Workflows¶

  • Administrative operations
  • Reporting and analytics
  • User management and access control

Session 5: Edge Cases and Exception Flows¶

  • Error handling scenarios
  • Rare but critical business cases
  • Recovery and compensation workflows

Next Steps¶

  • Prepare for async/batch process review in Session 6
  • Consolidate workflow documentation
  • Identify potential microservice boundaries based on workflows
  • Distribute functional requirements for stakeholder review
