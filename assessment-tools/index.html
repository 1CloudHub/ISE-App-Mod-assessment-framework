Assessment Tools for Team Members¶

This page provides detailed information about the tools used by the assessment team, including installation instructions, configuration guidance, and best practices for effective usage during assessments.

Core Assessment Tools¶

Amazon Q Developer¶

Amazon Q Developer is a generative AI-powered assistant that significantly accelerates the assessment process by automating code analysis and documentation tasks.

Installation and Setup¶

  1. Install and Update AWS CLI: 

    pip install awscli
pip install --upgrade awscli

  2. Install the Q CLI Plugin: 

    aws configure add-plugin q

  3. Configure AWS credentials: 

    aws configure
    Enter your AWS Access Key ID, Secret Access Key, and preferred region.

  4. Verify installation: 

    aws q cli help

Usage in Assessment¶

  1. Code Analysis: 

    aws q cli analyze-code --path /path/to/codebase --output analysis.md

  2. Generate Diagram Code: 

    aws q cli generate-diagram --type c4-context --from-code /path/to/codebase

  3. API Documentation: 

    aws q cli document-api --path /path/to/api --format openapi

Best Practices¶

  • Start with high-level analysis before diving into specific components
  • Use the --filter option to focus on specific languages or frameworks
  • Validate AI-generated content against actual code behavior
  • Use the --explain flag to get detailed reasoning behind recommendations

D2 Diagramming Tool¶

D2 is a powerful declarative diagramming tool that enables the creation of professional architecture diagrams using simple text-based syntax.

Installation and Setup¶

  1. Install D2: 

    # macOS
brew install d2

# Windows (using Scoop)
scoop install d2

# Linux
curl -fsSL https://d2lang.com/install.sh | sh -s --

  2. Install Graphviz (dependency): 

    # macOS
brew install graphviz

# Windows
scoop install graphviz

# Ubuntu/Debian
sudo apt-get install graphviz

  3. Install VS Code Extension:

  4. Open VS Code
  5. Go to Extensions (Ctrl+Shift+X)
  6. Search for "D2"
  7. Install the D2 extension

Usage in Assessment¶

  1. Create a new diagram file: 

    # Create a file with .d2 extension
touch architecture.d2

  2. Basic C4 Context Diagram: 

    # Sample C4 Context Diagram
title: {
  label: "System Context Diagram"
  near: top-center
}

Customer: {
  shape: person
}

LegacySystem: {
  label: "Legacy Application"
  shape: rectangle
}

ExternalSystem: {
  label: "External System"
  shape: rectangle
}

Customer -> LegacySystem: Uses
LegacySystem -> ExternalSystem: Integrates with

  3. Generate diagram: 

    d2 architecture.d2 architecture.png

Best Practices for D2 Diagrams¶

  • Use consistent naming conventions across all diagrams
  • Leverage D2's themes for professional-looking diagrams
  • Create separate files for different levels of the C4 model
  • Use comments to document complex relationships
  • Version control your diagram files alongside code
  • Follow the C4 model hierarchy for architectural diagrams
  • Use appropriate shapes and colors to distinguish different types of components
  • Keep diagrams focused on a single aspect or level of detail

Creating D2 Flow Diagrams with Amazon Q Developer¶

Amazon Q Developer can help generate D2 diagram code for flow diagrams:

  1. Using the CLI: 

    aws q cli generate-diagram --type flow --description "User authentication process with two-factor authentication" --output flow-diagram.d2

  2. Using the Chat Interface:

  3. Start a conversation with Amazon Q Developer
  4. Describe the flow you want to diagram: "Create a D2 flow diagram for user registration process"

  5. Refine the diagram through conversation

  6. Example Flow Diagram Code: 

    # User Registration Flow
direction: right

start: Start {
  shape: circle
}

form: "Fill Registration Form" {
  shape: rectangle
}

validation: "Validate Input" {
  shape: diamond
}

email: "Send Verification Email" {
  shape: rectangle
}

verify: "User Verifies Email" {
  shape: diamond
}

complete: "Registration Complete" {
  shape: rectangle
}

error: "Show Error Message" {
  shape: rectangle
}

end: End {
  shape: circle
}

start -> form
form -> validation
validation -> email: Valid
validation -> error: Invalid
error -> form
email -> verify
verify -> complete: Verified
verify -> error: Not Verified
complete -> end

  7. Best Practices:

  8. Provide clear descriptions of the flow
  9. Specify the actors and systems involved
  10. Mention decision points and alternative paths
  11. Include error handling scenarios

Installing D2 Extension in VSCode¶

To install and configure the D2 extension in Visual Studio Code:

  1. Open VSCode Extension Marketplace:
  2. Click on the Extensions icon in the Activity Bar (or press Ctrl+Shift+X)

  3. Search for "D2"

  4. Install the Official D2 Extension:

  5. Look for "D2" by "terrastruct" in the search results

  6. Click "Install"

  7. Configure the Extension:

  8. After installation, click on the gear icon (⚙️) and select "Extension Settings"
  9. Configure the path to the D2 executable if it's not automatically detected

  10. Set your preferred theme and layout engine

  11. Using the Extension:

  12. Create a new file with .d2 extension
  13. Write your D2 diagram code
  14. Use the preview button in the editor to see the diagram

  15. Export to PNG, SVG, or PDF using the export button

  16. Keyboard Shortcuts:

  17. Alt+D to open the preview panel
  18. Ctrl+S to save and update the preview

  19. Ctrl+Shift+P and type "D2" to see all available commands

  20. Extension Features:

  21. Syntax highlighting
  22. Live preview
  23. Export to various formats
  24. Code snippets for common diagram elements

  25. Theme switching

  26. Troubleshooting:

  27. If the extension doesn't work, ensure D2 is installed on your system
  28. Check the VSCode output panel for any error messages
  29. Verify the path to the D2 executable in the extension settings

For more information, visit the D2 Language Official Documentation and the D2 VSCode Extension page.

MkDocs Documentation Framework¶

MkDocs is used to create and maintain the assessment documentation in a structured, searchable format.

Installation and Setup¶

  1. Install MkDocs and extensions: 

    pip install -r requirements.txt

  2. Start the documentation server: 

    mkdocs serve

  3. Access the documentation: Open a browser and navigate to http://localhost:8000

Usage in Assessment¶

  1. Create new documentation pages: 

    touch docs/new-assessment-page.md

  2. Update navigation: Edit the mkdocs.yml file to include new pages in the navigation structure.

  3. Build documentation for distribution: 

    mkdocs build

Best Practices¶

  • Use consistent heading structure across all documents
  • Include diagrams generated from D2 in your documentation
  • Link related documents for easy navigation
  • Use admonitions for important notes, warnings, and tips
  • Regularly commit documentation changes to version control

Tool Integration Workflow¶

The assessment tools are designed to work together in an integrated workflow:

  1. Discovery Phase:
  2. Use Amazon Q Developer to analyze codebase
  3. Document findings in MkDocs

  4. Create initial context diagrams with D2

  5. Analysis Phase:

  6. Generate detailed diagrams with D2
  7. Document component relationships

  8. Use role-specific tools for deep analysis

  9. Documentation Phase:

  10. Consolidate findings in MkDocs
  11. Generate final diagrams

  12. Prepare deliverables

  13. Presentation Phase:

  14. Export documentation to customer-friendly formats
  15. Present findings using generated diagrams
  16. Provide recommendations based on analysis
